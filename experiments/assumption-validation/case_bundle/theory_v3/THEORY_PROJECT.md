# Agent 本体经济学理论项目

当前项目把 `lean/AgentMicrofoundations/FoundationCore.lean` 设为可单独构建的地基入口；完整聚合入口还包含辅助数学与案例模块，不应把其 theorem inventory 条目数解释为理论贡献数。地基承诺和核心条件推论见 [`FOUNDATION_CORE.md`](FOUNDATION_CORE.md)；Lean 可形式化的核心研究目标及完成判据见 [`CHOICE_LAW_RESEARCH_PROBLEM.md`](CHOICE_LAW_RESEARCH_PROBLEM.md) 和 `lean/AgentMicrofoundations/ResearchTargets/ChoiceLawProblem.lean`。实验限制准入规程单列于 [`EXPERIMENTAL_MODEL_ADMISSION.md`](EXPERIMENTAL_MODEL_ADMISSION.md)；它是工作流，不是 Lean 命题、公理或经济学理论。

## 项目约定

这是一个 Lean 驱动的持续理论项目。数学定义、假设和证明以 `lean/` 中可编译的 Lean 声明为正式来源；论文草案、研究报告和 trace 解释是这些形式结果的科学解释层，不代替形式证明。任何结果只有在前提写清、Lean 声明通过编译和公理审计后，才能登记为“已形式证明”。Lean 证明不自动证明假设适合现实，经验有效性须单独记录。

### 研究范围：案例分析的微观理论工具

项目目标是建立一套以 agent 本体为观察单位、可对具体 agent-society 案例作描述、机制分析、条件预测和拒绝判断的微观框架；当前不主张建立对任意 agent、制度和规模普遍成立的完整经济学，也不试图证明 agent 具有自主性或其经济行为必然涌现。论文实验的角色是案例分析和理论外部检验，不是公理来源，也不是普遍定律的证明。

所有案例都必须先声明主体身份与系统边界，再分开记录可见条件、agent 提议、机制执行、核验生产、资源/权利义务变化和后续状态。信用、承诺、产权、外部性、议价、均衡、福利等不作为未加区分的通用公理；若案例包含这些对象而分析主张依赖它们，就必须启用相应模块，否则对该主张标记为不可判定。模型描述主体/环境规律，condition 是 model 的状态或信息，mechanism 是独立的制度映射；机制披露可以进入主体输入，机制内生或与 prompt/权限共同变化时，不得伪称为“只替换机制”的比较。

每个实证主张须分级为边界描述、事件重建、结构相容解释、因果效应、条件预测或跨案例运输，并分别列出证据要求和拒绝规则。资源归属无法核验、提议与执行无法区分、账本无法对账、竞争机制无法排除、留出预测失败或运输条件不成立，都必须使主张相应撤回或降级。Lean 证明只验证形式推理，不提高经验主张等级。逐条审稿建议的采纳/收窄及 Smallville、iLands、CTF 案例映射见 [审稿建议处置与案例分析范式](审稿建议处置与案例分析范式.md)。

### 两个研究层次，以及它们之间的适用性闸门

论文和 Lean 项目应把工作拆成两个层次，中间用显式的案例映射连接：

1. **可复用的理论地基。** 定义以 agent 为主体的状态、可见输入、条件响应、资源/计算、生产、制度执行和状态转移；推出可计算的条件分布、识别边界和拒绝规则。它提供别人分析不同 agent-society 案例时能复用的概念、Lean 接口和推理工具，不声称替任意平台预先提供行为规律。
2. **案例化结构模型。** 对 CTF、Smallville、iLands 等具体环境，逐项把日志变量映射到上述对象，并说明哪些响应/生产/分配核由设计已知、哪些须从数据估计、哪些不可识别。冻结模型和预测后，再对案例数据检验；CTF 是当前案例，不是理论公理的来源。

二者之间的**适用性闸门**不可省略：若资源不属于主体边界、prompt 或机会菜单不能重建、提议与机制执行混在一起，或账本/时间戳无法核对，则相关理论命题在该案例上是“不可判定/不可实例化”，而不是已验证或自动被否定。若输入、状态和机制可以重建，但留出概率落在理论允许范围之外，则拒绝该案例化模型；若吻合，只能说通过了该项检验，不能据此证明地基普遍成立。

因此，Lean 适合验证可复用的数学接口、条件推论与不可识别结果；具体案例模型还需有数据导入/核算层、参数识别层、预测层和留出拒绝报告。形式证明的可复用性与案例预测的经验可信度是两种不同的质量，不能以其中一种代替另一种。

### 范式优先级：不以定理数量代替理论成熟度

本项目的对象是 agent 作为持续运行的计算主体本身。理论建设按五层分开：**主体身份/构成/状态**（本体定义）→ **条件响应、生产和状态更新**（待识别的行为与生成规律）→ **条件化模型**（上述对象及其外生环境）→ **独立机制**（在模型可行集合内执行提议）→ **可拒绝的推论**（定理与可观测预测）。条件是模型状态或参数，不是机制；机制可能被 agent 观察，此时相应制度信号进入响应输入，但不能把执行规则和响应规律合并。

资源必须约束 agent 自身的机会、执行、生产或继续运行，才构成本项目所说的 agent 经济关系。记录一个余额、研究者付出 API 费用、或 agent 说出交易意向，都不单独满足这个条件。响应核不预设理性、偏好稳定或主体独立；这些只能作为明确、可被拒绝的行为限制。人口规模变化的预测还须明列响应、生产和机会结构的运输限制，不能从 6 人案例自动外推到 3/4/5 人或大规模社会。

Lean 的正式对象结构应服务于这套分层。增加声明前先问：它是否澄清主体边界、修正模型/条件/机制的混层，或推出新的可观测限制/非识别边界？若只把同一算术改写为另一条定理，不作为理论深化。定义接口的正确性、形式证明的正确性和经验前提的适用性分别审查。

## 每轮理论迭代

1. **提出一个可反驳的问题。** 指定主体状态、条件、结果事件及竞争解释，不先把要解释的行为塞进假设。
2. **先形式化最小对象。** 定义有限资源/状态、上下文生成、个体响应、联合生产、机制执行和账本转移；所有独立性、交换性或同质性条件都必须是显式假设。
3. **写出结果或反例。** 证明一般规律，或构造反例准确说明现有微观信息不足以识别某项预测。反例也是理论进展，但不应冒充普遍规律。
4. **运行验证闭环。** `python3 verify_micro.py` 会先从 Lean 源码重建 `Audit.lean` 与 `THEORY_INDEX.md`，再运行 `lake build`、检查每个 theorem 的公理依赖，并写入源码哈希清单。不得手工编辑这两个生成文件。
5. **映射到数据。** 对每个结果登记所需 trace、现有数据是否可识别、可能的证伪条件。Lean 结论与经验判断必须分栏。
6. **跨平台核验。** `./verify_miao.sh` 将整个 Lean 模块树送到 Linux 主机，执行 `lake check` 默认内核检查及公理审计。

7. **假设准入审计。** 案例模型中的每个经验限制必须登记一个可复跑的低成本检查、检查单位、拒绝阈值/规则和失败后的撤回动作。`analysis/validate_case_assumptions.py` 生成 JSON 登记表；`verify_micro.py` 拒绝缺字段、无拒绝规则或未经验证却被用于点预测的限制。不能设计简单直接检验的行为规律，不作为假设；保留为未约束核并报告部分识别或“不输出点预测”。数学前提由 Lean 验证，经验映射由日志/后端审计，两种证据不能互相替代。

## 理论主线：每个证明必须服务于什么预测

本项目不以定理数量作为进展指标。agent 本体经济学的微观地基需要把计算主体及其输入、条件响应、机制执行、生产与状态更新连成一条可审计的推理链。这个流程图式描述本身不构成数学结果；Lean 里的有限轨迹组合也只是给定条件核后的计算定义。

证明只有在完成以下工作之一时才进入主线：

1. **划定主体结构不变量。** 固定计算构成、完整输入及解码/协议条件时，哪些响应分布必须相同？当两种预算都覆盖某个有限前缀时，该前缀及依赖此前缀的提议性质是否保持、哪些后缀性质不受保证？这回答“以 agent 本体为对象后，计算实现带来什么不同于抽象随机 agent 的约束”。
2. **给出行为规律缺失时的尖锐边界。** 若资源、机会和生产可行性没有限制选择核到足以区分结果，能否证明任意目标概率仍与基础结构相容？这回答“为何不能从资源或实验频数直接推断偏好、个体分化概率或规模规律”，并指出预测所需的最少新增识别信息。
3. **把已识别的主体规律转成反事实预测。** 在固定主体响应与生产规律、只替换机制的情况下，精确计算提议、执行、核验、资源及未来轨迹分布；或给出在部分识别下仍然成立的概率界。这回答“机制怎样促进/抑制 agent 经济状态”，并支持对未实际运行的配置做可复算预测。

当前正式主线因此是：`Ontology.lean` 定义主体响应、可见条件、机制、生产及账本的分层接口；`AutoregressiveResponse.lean` 给出计算构成对响应核的可拒绝限制；`ResponseIdentification.lean` 证明没有响应限制时，资源/可行性本身不能点预测行动概率；`FiniteDynamics.lean` 将给定的单期规律组合为有限期轨迹预测。机会分配、会计、CTF 和其他专题结果，只有在收窄主线的识别集、给出规模/机制可复算比较，或作为明确标记的案例时才属于核心贡献。

新增 `TemporalIntersectionBounds.lean` 给出了有限期持续事件的分布无关概率包络。若持续事件要求每一期通过可观测门槛，则

\[
\max\{0,1-\sum_t(1-p_t)\}\leq P(\text{持续})\leq \min_t p_t,
\]

其中 $p_t$ 是第 $t$ 期必要事件的边际概率。定理保留所有跨期依赖，不使用独立、平稳或 Markov 假设。`PersistentEventCase` 要求案例把 persistence 定义成逐期条件的合取；可以用轨迹重放直接检验。Lean 还给出上界、下界和任意有限期案例接口。对一般有限期数，项目不声称外界总是尖锐；若案例分析需要两期的精确识别区间，可调用单独登记的通用概率辅助工具。边际区间过宽是信息不足的结论，不是用未经验证的独立性缩窄区间的理由。

`ExactTwoEventCoupling` 是一个通用概率识别辅助工具：只给出两期边际时，它计算未知依赖下的可达联合率区间。它不属于 agent 本体经济学的基础公理或原创行为规律，因此已从理论总入口与理论索引中分离，单独在 `lean/METHODS_INDEX.md` 登记。它只在具体案例需要该识别区间时作为数学工具调用。

对“参数是否实际进入计算”做了逐字段核查：Lean `CTFDesign` 当前有 46 个字段，其中 9 个被资源回放直接消费，1 个部分消费，1 个接入人口接口，11 个只用于时钟顺序校验，1 个 horizon 需由调用者另传，23 个仍需具体案例核绑定。自动化表和漂移检查见 `analysis/audit_ctf_design_coverage.py` 与 `CTF_PARAMETER_COVERAGE.md`。因此统一情景类型提供参数容器和有限核计算器，但参数被记录并不意味着其作用已实现；未绑定的设置不能用于宣称已完成的反事实数值预测。

为实际 v2 CTF 的时间与机会规则，`AuthorityWorldV2Clock.lean` 使用配置里的日长、分配截止、工作截止、选举登记时间、任务寿命和运行天数，形式化半开时间窗与到期时点。它证明分配和工作机会不重叠，并对冻结的 900 秒正式设置核验 60 秒分配窗、780 秒工作窗及最后 120 秒选举窗。零 API 后端审计在 8 份 agent-econ v2 配置逐项检查实际 Python gate。它补上的是 v2 案例映射，不等于通用 `CTFDesign` 的抽象时间字段均已编入转移律。

`AuthorityWorldV2Election.lean` 继续把 v2 的职位选任从“可调设计字段”推进为实际可计算的制度映射：以已记录候选人、显式投票、存活者集合和 seed 决定的缺票/并列选项为输入，逐分支计算无候选、全员候选或 plurality 结果。形式结果只依赖有限名单和票数；普通计票分支中当选人必属候选集合。零 API 审计直接调用后端 `_finalize_election`，覆盖无候选、全员候选及一例缺票补投形成的并列。映射的拒绝条件是后端分支、seed 标签、补票规则或实跑结果与 Lean 模型不一致；失败时该案例选任映射失效，其他理论层不随之修改。它仍不预测主体会不会参选、如何投票，也不将响应行为偷换成制度规则。

为把这条主线变成可直接计算的情景入口，新增 `ScenarioSimulation.lean` 的 `FiniteScenarioFamily` 和 `IndexedFiniteScenarioFamily`。每个设置提供明确去重的有限 agent 身份列表，并要求证明它覆盖模型中的全部 `Agent` 身份；人口扫描可令身份类型随设置变化（如 `Agent setting := Fin n`），因此人数由模拟边界而非额外的休眠标记决定。每个设置还提供计算主体模型/响应核、机制、生产与资源更新、下一期 condition 转移及初始分布；`forecast` 递归合成任意有限期的精确有理概率分布，`eventProbability` 和 `expectedStatistic` 可计算生存、分工、获配、成功、能量与其他路径结果。配置类型由案例定义，因此可包含有无投票、任务菜单/生产机会、分配窗口、初始能量、推理能耗、基础代谢和奖励等参数，不固定 4+2 或六人设计。比较“只改机制”时须固定经济模型/响应核并只替换 admissible institution；若设置还改变 prompt、模型状态或响应核，则那是不同 condition/主体输入，必须一并进入该场景映射。

`MechanismCounterfactual.lean` 将这个要求落实为单独的机制干预族：各处理共享同一模型、响应 constitution、agent 身份类型、初始 law、生产/资源技术和上下文转移，只允许 institution 随 treatment 变化。若两机制在同一状态给 agent 的披露信号相同，`Ontology.equal_disclosure_implies_equal_proposal_law` 给出当轮提议分布完全不变；执行和产出仍可不同，并通过资源、内部状态、下一期 condition 反馈到后续提议。若当轮提议分布也变化，预先定义的机制分解即被拒绝，除非能审计到披露/完整输入同时变化。该结构允许数值比较即时执行效应与跨期反馈效应，不需要重跑当期模型调用；是否能把该预测用于 CTF，还需把现有世界配置和经验响应核实例化。

这给出了**可运行的理论数值计算接口**，但不意味着只填实验环境参数就能无条件算出 agent 的点预测。每个设置还必须给出或校准主体响应、联合依赖、生产和上下文转移规律；在响应规律未受限制时，`ResponseIdentification.lean` 仍允许目标行动概率遍及完整 `[0,1]`，只能报告识别区间，不能伪造唯一数值。现有 CTF trace 可用于零 API 离线校准/留出裁决；若要把它运输到不同人口或新制度，必须冻结并检验对应的核运输限制。形式接口能统一任意案例的参数入口，具体 CTF 参数族与其留出数值预测仍是接下来要完成的案例实现。

## 现阶段能声称的理论内容与边界

- **可由主体计算结构推出：** 固定核、完整 prompt、解码与 parser 条件时的输入—响应限制；两个预算都覆盖的任意有限前缀，其边际分布不随更大生成上限改变。只依赖该前缀的协议将此前缀不变量传递到提议分布。它们给出可直接拒绝的实现层预测，不推出某类经济行动更常发生。
- **可由资源账本推出：** 在资源确属 agent、成本规则公开且计算预算受其约束时，余额限制可支付生成轨迹。`affordable_balance_change_proposal_event_bound` 将余额映射为可负担生成预算，再把提议事件概率的两向变化限制在两种预算下 parser 与共同前缀解码器的分歧概率之和以内。新增的 `affordable_budget_saturates_at_technical_cap` 与 `saturated_balances_same_prompt_imply_equal_proposal_law` 给出饱和区间：余额能覆盖技术上限后，纯预算渠道不再改变提议分布，前提是计算构成和完整 prompt 相同。因此，在该区间发现分布变化，可拒绝“固定 prompt 下只有预算通道起作用”的案例模型；不能据此拒绝 prompt、状态或机制披露带来的其他资源通道。两项结果都还没有在现有 CTF 数据上实例化。
- **资源与行为不可混同：** `ResourceRelevant` 只说明资源状态会改变可行机会菜单；`resource_relevance_does_not_imply_resource_sensitive_proposals` 给出反例：同一个计算主体可以面对不同菜单，却按忽略菜单的固定响应核产生同一提议分布。因此从“资源约束真实存在”到“agent 会因资源改变行动”之间，必须另有可测、可拒绝的响应限制。不能把资源存在或资源影响预算偷换成理性选择。
- **可由一般形式组合推出：** 给定完整响应、执行、生产、状态及上下文转移核后，有限人口/有限期结果分布可逐步计算。这里的预测输入是结构化规律，不是“agent 理性”假设。
- **没有响应规律时不可推出：** 谁提议、谁获配、个体分化概率、不同人口数下的具体行为概率。`ResponseIdentification.lean` 的尖锐结果表明，在两个结果都可行且不再限制响应核时，目标事件概率识别集仍是整个有理区间 `[0,1]`。因此任何点预测都必须来自单独说明并可检验的计算响应限制或案例校准。
- **机会不均如何转成持续角色分化：** `OpportunitySpecialization.lean` 将“每个正概率分配结果都有获配者和未获配者”与同一固定响应函数连接起来。若共同初始上下文按获配状态进入两个可观测、前向不变的上下文区域，而且同一响应函数在两区域选择不同角色，Lean 推出分配彩票下群体持续角色分化的概率为 1。证明不需要独立分配、匿名性或理性选择，也不识别哪些 agent 分化。模块还给出一个显式的整数强化例子：初次获配把同一基准上下文分到 $+1/-1$，固定响应规则与角色一致地强化相应上下文，满足条件时角色分化持续。实质限制是机会暴露必须改变后续上下文，并让 agent 留在不同响应区域；若上下文可跨区、区域内角色响应不异，或分配结果可能全有/全无机会，该预测不适用。当前 CTF 汇总切片没有逐 agent 的提议—指派—上下文链接，尚不能检验这些前提，因此不能把该定理写成对 24 个 world 的事后证明。整数例子说明定理前提可满足，不是对真实 LLM 的经验主张。
- **资源怎样给角色分化设定可计算的寿命界：** `ResourceThresholdPersistence.lean` 以生产后余额为上下文，避免直接假定抽象的“不变区域”。若生产性曝光后的余额为阈值 $	au$ 加余量 $m$，非生产性余额低于 $	au$，后续每期两类主体承受相同非负消耗 $d$，Lean 精确证明生产者第 $t$ 期的阈值行动为活跃，当且仅当 $td\le m$；非生产者保持低于阈值。因此任何满足 $Hd\le m$ 的有限预测期内，若每个正概率的生产分配结果都同时包含生产者和非生产者，群体角色分化事件概率为 1；一旦余量耗尽，生产者的阈值响应关闭。它是有限期边界，不是永久分化定律。若生产成本随角色变化、后续收益补充资源或响应不是固定阈值规则，需要扩展转移模型。当前 CTF 救援切片只能复核部分转移和下一次消耗，不能关联多期响应，尚未检验这一寿命界。
- **净流量何时不足以预测资源状态：** `ResourceThresholdPath.lean` 形式化逐事件存活门槛。若路径最终仍存活，期末余额等于初始余额加事件净流量；若期间可跨过生存门槛，同一初始余额和同一净流量仍可能产生不同存活结果与期末余额。该反例区分可交换的加总账本与改变继续运行可行性的中途门槛。它是结构边界，不声称 CTF 后端已采用逐事件死亡裁决；案例映射须核实真实结算时序，否则用加总账本。
- **自回归形式本身也不能给出选择方向：** 新增 `AutoregressiveIdentification.lean`，用固定 prompt、固定停止规则和固定的“首 token 即提议”解析器证明：只要 next-token 概率核可以任意变化，自回归 constitution 类能实现 `[0,1]` 中任意有理提议概率，端点也都能实现。这不是说某个固定部署模型能任意行动；固定 kernel、prompt、budget 和 parser 后，`proposalLaw` 已精确计算出唯一概率律。它说明无法从“LLM 是自回归模型”这一架构事实继续推导经济选择偏好或行动方向。要向前一步，必须有该主体/上下文的 next-token 条件概率（或可检验的 kernel 限制），连同完整 prompt、停止/解析协议；当前 CTF 汇总结果没有这些量，不能把 token 行为规律凭空补出来。
- **实验的逻辑角色：** 实验只检验冻结后的理论限制或作为一个有限案例估计响应/生产核；不用于把观察到的分工、成功率、分配概率写回基础假设。案例拟合与理论推导必须分开报告，留出 world/设置才是预测检验。

对“相同初始 prompt、后续角色分化”的主案例，待解释的不是一次轨迹是否相同，而是条件响应分布为何变化。相同完整输入只要求条件分布相同，不要求随机实现的动作相同。若后续任务菜单、资源、可见制度信号或上下文已变化，固定响应规律可对新输入给出不同分布，这构成状态反馈解释；若完整输入和计算构成都相同而响应分布仍不同，则计算表示或状态测量被拒绝。案例要用逐期输入、提议、执行、生产和状态记录区分这三种情况，不能由最终角色标签推断“偏好改变”。

### 冻结地基后再校准案例，不让案例反向决定公理

理论冻结版本 `THEORY_FREEZE_0.5.md` 是数值案例模型的前置合同：它把对象定义、数学推论和需验证的案例限制分开。两期耦合界已归为通用数学辅助工具，不作为 agent 经济学新理论。主体响应由案例核表示，制度把提议映射为执行，生产、账本和状态转移生成下一期输入；任何一层的核未知时，模型输出识别区间或拒绝点预测。CTF 的任意人口、投票/分派机制、机会菜单、时钟、能量、任务奖励/成本、终止与版本参数已进入 `CTFDesign`，并由 `FiniteScenarioFamily` 的联合有限核逐期生成精确有理数预测。设置参数不需要对应一条新公理；它们只是模型/机制/状态转移中的可调输入。Lean 数值模拟要喂入的是完整案例律，而不是参数列表本身。

案例实例化按固定顺序进行：先把已冻结的理论定义和拒绝条件编译为 CTF 输入映射；再用现存逐次输入、提议、分派、核验与账本离线构造候选案例核；然后锁定候选核及其参数、支持范围和世界级拒绝阈值；只有理论敏感而现有轨迹不支持的响应概率，才用少量同 checkpoint 的重复 API 请求校准；最后才开新 world 作真正留出裁决。API 试验不负责证明或修订地基，只判定被冻结的 CTF 案例预测是否通过。若政策参数把 agent 带到历史未覆盖输入区，输出敏感性区间或“需最小校准”的拒绝状态，不能静默沿用历史频率。

2026-10-25 的全归档审计已经证实，原始数据保存 45,180 条完整 gateway 输入与对应响应，因此“输入不可重建”不再是有效限制。所有 exact request signature 唯一，响应核的同输入随机波动无法从历史重复估计；这是一个明确的识别事实，解决途径是按上面的冻结顺序，仅对影响预测的 unsupported state 做低成本重复调用，而不是停留在资料不全的判断上。

同日新增 `analysis/validate_case_assumptions.py`，只读既有 CTF 表和 pilot 记录，不调用模型 API。它自动核验 24 个 world 的账本、任务映射、结果事件；逐 agent-day 检查能量余额与存活标记；并重算 stage-2 回顾性预测误差和 pilot 配对计数。审计结果显示，能量—存活桥接只能用于明确的操作性制度，不能作普遍假设；stage-1 任务频率基线在 stage-2 的四格均超出事后 5pp 筛查线，故该案例点预测被拒绝。检查结果连同代码和数据哈希进入 Lean verification manifest。详细分层与拒绝规则见 `THEORY_FREEZE_0.5.md`。

新增 `TemporalIntersectionBounds.lean` 后，案例还可以在不重建完整跨期联合核时，用逐期生存/可参与边际率得到无独立性区间，并在终止为吸收状态时从终期边际精确恢复持久参与比例。该接口要求每个 outcome 表示同一有限 horizon，逐期条件及 terminal persistence 标签能由已审计转移规则重放；若复活、刷新余额、删失或不同观测期造成不等价，拒绝此接口，回到完整轨迹模型。现有 CTF 做了一个严格限于描述性的 H=8 应用：在每个 world 的六名具名 agent 中，24/24 无复活，terminal alive share 与贯穿前 8 天的 persistence share 一致；所有观测均落在分布无关区间内。这里的边际和 persistence 来自同一条历史轨迹，因此只验证案例映射与会计，没有检验事前预测，也不能外推到新 world。

新增 `ResourceSurvivalBound.lean` 将资源可行性提升到任意有限随机余额分布：对统一正准备金 $d$，达到准备金的账户数 $N_d$ 满足 $dk\Pr(N_d\ge k)\le E[S]$。它允许分配、生产及主体结果任意相关，不假设理性、独立或匿名，并有等号可达的构造，因此是对任意制度都成立的资源上限。这个结果不直接等于 CTF 存活预测：CTF 的真实死亡阈值为零，代入零准备金后界退化。要预测撑过下一次运行周期，须从后端时序和强制基础扣费导出正准备金，并把它作为清晰可检验的案例量；不能把选择的 $d$ 说成自动成立的生存阈值。

以后不为“补齐模块”而扩张 Lean。新结果先写清它改变了哪个预测对象、收窄了哪个识别集或支持了哪个跨配置运输，再决定是否值得形式化。若只是已知定义的机械展开，留作实现细节，不作为理论贡献。

## 理论与案例的证据边界

- 理论原语和定理必须由研究对象的定义及一般结构约束推出，不能因为某个实验结果出现才把该结果写成公理或普遍假设。
- 实验先作为理论冻结后的案例实例：配置只代入一般模型的参数/机制，有限轨迹只作为模型生成的一次随机实现或有限样本；它们可检验、反驳或校准理论，不能单独证明覆盖所有场景的假设。
- 若案例不符合理论预测，应先定位是测量、模型域、行为核、机制核还是状态转移出了错；不得事后增加只适配该实验的公理来保护理论。
- Lean 的一般命题放在通用模块；配置具体数值的推论放在 `AgentMicrofoundations/CaseStudies/`，并且以 import 通用定理的方式派生。
- 行为、任务成功和跨期状态可有随机性；需要概率预测时须显式定义条件核和随机化单位。观察到一次结果不能替代概率规律。
- A1–A8 是按问题选用的结构/行为模块，不是需要全部无条件接受的公理包：资源闭合和执行链用于定义 agent 经济事件；续存阈值、计算成本、生产技术只在对应研究域内适用；训练形成/行为响应是待识别规律；提议/执行/核验记录是识别条件。
- 本体分析须显式区分持久身份、计算构成（模型/部署/系统指令/工具）、变化中的内部与资源状态、条件响应规律。固定计算构成不等于固定响应；响应规律是要识别的对象，不作为理性假设。经济后果须连接到案例声明的资源、核验产出、可执行机会、权利/义务或续存状态；当前基础事件类型未编码权利/义务，涉及它们时必须启用扩展模块。
- “计算型 agent 经济”的结构强度分两层：`ComputationalAgentEconomy` 允许任意已给定的响应规律；`ResourceCoupledComputationalEconomy` 才额外要求自有余额决定 token 上限、解析结果保留生成长度、且生成成本事件进入闭账账本。只有后一层支持“资源约束计算”的可行性结论。成本事件当前要求被记录，但尚未证明每个相同事件恰好记账一次；该精确性仍属开放义务。
- 当前 Lean 模型中，身份可作索引；计算构成通过可选因子化细化与变化中的状态/输入分开表示。该限制是否适用仍由数据检验，不以增加声明数为目标。

## 两层研究设计：可复用地基与案例模型

理论交付分成两层，二者不能互相替代。

1. **可复用地基**（`Ontology.lean` 及其通用模块）规定案例必须区分的对象，并证明不依赖某个 CTF 配置的结构命题或识别边界。它的职责是让别人能把别的 agent society 映射进来，并知道从可观测条件最多能推出什么；它不承诺对任意模型给出数值预测。
2. **案例模型与检验**（`CaseAnalysis.lean`、`CaseStudies/`）将具体世界、个体资源、响应/生产规律、机会分配与结果事件映射到地基。规律只能用校准数据拟合或由外部制度定义；预测在留出数据上检验。`fitted_foundation_invariant_to_holdout` 形式化：固定同一个拟合函数和校准行后，改变留出行不会改变拟合参数；这不证明研究者构造拟合函数时没有看过留出数据，故仍需预先冻结拟合流程。观测计数相对期望计数的容差带仅是描述性偏差筛查，不能单独称为统计拒绝检验。新增 `ExactFiniteCaseTest` 要求案例给出评估单位（例如 world 向量）的**联合零假设抽样分布**，并以 Lean 证明其精确拒绝概率不超过预设水平；它允许任意依赖，但不从边际分布自动推得联合分布。进一步，若某个具体样本落在拒绝域内，其零假设点概率也必不超过该水平。样本单位、依赖结构或有限样本抽样规律缺失时，检验保持未实例化，不伪报显著性。

这两层在实际分析中按“**地基 → 案例模型 → 案例裁决**”运行：地基给出通用定义、识别集与推理规则；案例模型把 CTF、Smallville 或 iLands 的机制、资源、响应和生产映射为这些对象；案例裁决再问数据是否满足模型前提、预测是否落入预先规定的接受域。第三步不是第三套理论，而是避免把 Lean 的条件定理误报为已经通过现实检验。地基可以跨案例复用；行为核、机制、资源单位和生产规律通常不能无条件搬运。

通用命题 `anonymous_fixed_productivity_predicts_group_next_activity` 展示地基怎样产生规模比较静态：若整个“分配—生产”联合规律对 agent 重标号不变，在所有正概率结果中每轮成功产出人数固定为 $k$，且目标组每个成员都满足事先定义的资源阈值跨越条件，则

\[
N\,\mathbb E[A_{G,t+1}] = |G|\,k,
\]

其中 $N$ 是人口规模，$A_{G,t+1}$ 是组内下一期活跃人数。固定成功人数只约束分布的正概率支持；零概率的列表行不构成经济状态，也不应导致模型被拒。命题不靠独立性或理性假设，但依赖**联合过程匿名**和**固定成功人数**；仅分配器匿名而成功率依身份变化并不够。它预测期望，不预测谁获配、实现人数分布或分化概率。改变 $N$ 或 $|G|$ 时，只有上述规律能运输到新配置才可使用该式。前提可通过身份置换检验、逐轮成功人数与资源阈值测量来拒绝；一旦拒绝，必须退回异质边际/联合核的部分识别，而不能继续引用点预测。这个命题是通用理论的一个强限制示例，不是 CTF 实验的核心预测；实际案例应直接把任意身份组合作为对同一联合记录的查询，不预设 4+2 分组。

CTF 案例现在有独立于该 4+2 示例的实际观测实例。`CaseStudies/CTFTraceModel.lean` 把任意人口的一日记录表示为机会菜单、分配提议、机制执行、核验生产、资源变化和下一期活动，并证明任意身份子集及其补集对已执行任务构成精确划分。`CaseStudies/CTFArchive.lean` 则从逐任务归档生成 I1/I3、模型家族、难度层的经验槽位计数，并由 Lean 核对校准/留出数据、提议—执行约束和精确频率预测。4+2 仍只是通用理论的示例：案例读者可以选任意分组对身份级数据重新汇总，不需要假设 2:1、匿名分配或固定成功人数。`CTFModel.lean` 的阈值、匿名和固定生产定理继续保留为可启用的强限制，不能当作这 24 个 world 的既成事实。

当前可从 stage1 校准、按 model family × allocation regime × task tier 得到分配与核验产出的频率基准，再按原始 stage2 切分作回顾性留出诊断。它条件化于实际出现的任务槽，不预测世界何时终止或未来出现多少机会；stage2 共有 4 个 world、每个 family × regime 仅 1 个，且该简单频率模型是在看过归档之后定义的。因此它补齐了“地基—案例模型—数值预测”的可执行路径，但尚不能作为前瞻确认性检验或总体概率规律。实际结果显示分配计数预测在四个 holdout cell 均有 4 到约 15 个任务的误差；成功计数预测更接近，但 DeepSeek/I1 的预测误差约 2.29 个任务。若用回顾性 5 个百分点误差筛查，四个分配率预测均被拒绝，success rate 仅 DeepSeek/I1 cell 被拒绝；Lean 已核对这些计数判定。该阈值和模型均未在 stage2 揭盲前注册，所以只能作为本基准被拒绝的描述性结果，不能解释为显著性检验。预测失败应促使我们在新留出前完善并冻结状态案例核，而不是把误差写成新公理。

即使案例不能点识别联合获配—成功规律，地基仍可给出部分预测。`productive_exposure_bounded_by_assignment_and_success_marginals` 证明个体成功获配概率 $j_i$ 满足 $a_i+s_i\le 1+j_i$、$j_i\le a_i$、$j_i\le s_i$；汇总为 `group_productive_exposure_bounded_by_marginal_masses` 后，组内成功获配期望数位于 $\max(0,\sum_i a_i+\sum_i s_i-|G|)$ 与 $\min(\sum_i a_i,\sum_i s_i)$ 之间。此界不假设独立，也不把 $a_i s_i$ 当作交集概率。新生成的 `agent_day_panel.csv` 和 `task_panel.csv` 已把身份级获配与核验成功联结起来，所以任意预先定义的组都可以直接计算有限样本边际与组计数；但 24 个 world 是总体推断单位，嵌套任务/日期不能当独立重复，且仅 4 个 stage2 world 不足以为组级随机规律提供精确误差率。

对 CTF 可另启用一个更强、但须说明语义的支持限制：若每个正概率的 checker 成功都对应一个已获配 agent，则成功边际等于成功获配概率。`ProductionRequiresAssignment` 把该限制写成显式案例前提；`success_marginal_eq_productive_exposure_of_requires_assignment` 证明在此前提下成功事件质量与成功获配质量相等；`heterogeneous_group_next_active_mass_eq_success_marginal_mass` 因而把组级下一期行动概率总量直接化为各 agent 成功边际之和。此处不需要获配与成功的联合概率，也不假设独立，但仍需要识别成功边际和阈值 crossing。若成功可以在未获配时发生，该简化失效，应回到前述 Fréchet 区间或完整联合核。

另须区分“期望活跃人数”与“至少一人活跃的概率”。`heterogeneous_group_any_next_active_probability_bounds` 将后者的下界限定为组内任一已知个体活跃概率，上界限定为期望活跃人数（同时概率本身不超过 1）。这不识别组内活跃人数的完整分布，也不识别分化/集中事件的概率；跨 agent 依赖仍须由联合核或实验设计识别。CTF 接口分别提供四人组和两人组的对应界。

新增通用模块 `SequentialBounds.lean` 把单期规律接到跨期路径概率：若对模型定义域内每个完整状态，下一期事件的条件概率都在 $[\ell,u]$ 内，则连续 $T$ 期每期事件都发生的概率在 $[\ell^T,u^T]$ 内。若每个状态的单期条件概率都等于 $p$，则路径概率恰为 $p^T$。这里事件和下一状态可任意相关，状态可承载上下文、资源、角色和历史反馈；没有假设跨期独立、偏好稳定或 agent 理性。它的限制也很明确：需要逐状态统一的条件概率界；若只能估计总体边际率，不能套用幂界。该定理提供的是核已识别/校准后的动态部分识别，不从资源本身推出事件率，也不意味着当前 CTF 已满足或验证该限制。案例拒绝需按完整状态分层检查单期条件率，并用留出轨迹检验路径事件频率；若缺少状态记录或样本不足，结论标为未识别。

因此案例层的经验状态现可细分为：提议、执行、核验产出和资源变化均可从事件与 trace 重建；资源 ledger 已对 24/24 终态逐 agent 对账；任务机会与 task manifest 也完整联结。进一步的零 API 审计确认，24 个原始归档中包含 45,180 个完整 gateway exchange 的 `request.input`、工具 schema、model id 与响应。45,178 条与成功 `model_response` 对齐；1 条对应 context 索引中的 `model_error`，1 条没有 context 索引配对。另有 381 条 model_error 没有 gateway payload。全部完整输入签名唯一，因此历史归档可用于重建实际 agent-visible 输入与构造案例特征，但不能单靠完全相同输入重复来估计条件响应随机律。这个发现取代早先“完整请求尚待重放”的陈述：输入可重建，不是理论或建模障碍。后续需要做的是冻结响应/生产规律，并把它们放进有限期 simulator；不支持的状态必须给出预测区间或明确拒绝点预测。provider 内部未公开的预处理/tokenization 仍不等同于 agent-visible gateway request，也不作为本文理论公理。每个案例规律需报告校准支持数和留出误差；没有支持或没有明确抽样单位时，输出部分识别或不预测，不从实验现象倒推普遍假设。

配套的零 API action-set 审计把每条模型响应的工具调用与该次请求实际携带的 tools schema 对账：4 种 schema 中没有响应调用超出其 schema；I1 请求暴露 task-assignment 工具，I3 请求不暴露。因此 I1/I3 不满足“同披露、只替换执行器”的排除限制，agent 可提议动作集合本身就变了。要实例化该对比，必须把工具 schema/机会集变化放入条件响应输入层，再单独建模剩余执行规则；不能把两者合并成一个执行效应。请求级工具调用率只作描述，因为同一 world 内请求依赖且 schema 暴露不等于当时有可执行机会。

## 当前形式化模块

- `lean/AgentMicrofoundations.lean`：资源账本、续存、有限资源群体边界；新增对称两上下文 Markov 三期模型，形式化精确存活路径权重，并证明在同一成功边际下，完全交替/独立重抽/完全持续的续存率可为 1/2、3/8、1/2。
- `lean/AgentMicrofoundations/ComputationalEconomy.lean`：除群体响应边际桥接外，新增资源耦合精化：自有余额决定 token 最大预算，行动提议保留实际生成长度，成本事件进入显式闭账账本。Lean 推出由该资源预算生成的 trace，其线性 token 成本不会超过期初余额。这刻画“资源—计算”连接，不预测行动选择、解题产出或机会分配；其成本事件的唯一性及完整净额分解尚未证明。联合响应、生产和上下文转移仍需识别/校准，故该对象是有边界的预测接口，不是无参数行为理论。
- `lean/AgentMicrofoundations/Ontology.lean`：形式化主体身份索引、内部/资源状态、模型条件输入、条件响应核、联合生产/状态更新与独立兼容机制。`MechanismRule` 与 `AgentEconomyModel` 独立定义，`MechanismCompatible` 只约束模型—机制配对；`AdmissibleInstitution` 为动态预测显式携带该相容性证明。原始 `onePeriodDistribution` 可用于反事实规则比较，跨期 `FiniteDynamics` 则要求可采纳机制配对。`AgentEconomicEvent` / `hasConsequence` 是经济事件的操作定义：把资源、机会、核验生产、已记录的关系状态变化和继续运行分开记录；执行阶段单独记录，不会仅凭执行就被谓词认定为经济后果；裸提议也不满足。关系状态以“是否发生有记录的状态改变”进入事件接口，不预设其必然存在或采用统一合同语义。资源更新函数现显式接收提议、执行和核验产出，因此模型可以登记提议生成成本，即使机制随后拒绝它；成本是否归属于 agent 仍由应用账本说明。`ConstitutionallyFactoredResponses` 是可选、可拒绝的计算构成限制：相同构成及动态输入给出相同个体响应边际；不约束任意联合响应依赖，也不假设理性。资源反馈和可达性结果维持原有条件边界，不推出长期概率。
- `lean/AgentMicrofoundations/AutoregressiveResponse.lean`：把计算构成细化为固定的逐 token 条件核、停止 token 和固定行动解析器；上下文和 agent 状态编码为 prompt 与最大生成预算，预算依 agent 状态变化。`token_prefix_law_independent_of_larger_budget` 证明：只要比较的两个预算都覆盖某个长度，prompt 与 token 核固定时，该前缀的事件分布不受更大的生成上限影响。`prefix_sufficient_parser_proposal_law_invariant` 进一步证明，只依赖该前缀的协议在预算均覆盖前缀时，任意提议事件概率相同；首 token 结果是特例。新增 `proposal_event_budget_sensitivity_bounded_by_prefix_disagreement` 放松精确前缀解析限制：任意完整 parser 的行动概率变化，在两个预算下分别不等于某个固定前缀 decoder 的轨迹概率之和；前缀 token 分布相同，所以该界不需要预算效应单调，也不预测正负方向。若测得 parser 与前缀 decoder 很少分歧，这给出可拒绝的上界；若分歧率高，界会变松。案例检验需按主体保存完整 prompt、预算、token 轨迹和解析结果；仅有最终行动或成功率不足以计算该界。
- `lean/AgentMicrofoundations/ResponseIdentification.lean`：将可行性与选择分开，定义完全支持在可行提议上的响应分布；证明只要某结果及其补事件都包含一个可行提议，未受额外行为限制的响应核就能实现 $[0,1]$ 内任意有理概率。概率非负/不超过 1 的通用界与端点/全区间可达性共同给出精确识别集。它是“仅靠资源和生产可行性不能点预测选择概率”的尖锐不可识别定理，不是关于真实 agent 行为的经验断言。
- `lean/AgentMicrofoundations/ContextualResponse.lean`：形式化“上下文分布 × 条件响应核”的全概率分解，并证明每个正概率上下文中的条件事件概率若满足统一的 $[\ell,u]$ 界，任意上下文混合后仍处于该区间；零概率上下文无需满足该界。允许响应随上下文变化，不要求响应稳定或上下文独立；只有正概率上下文中的逐情境界本身是额外需给出/检验的规律。
- `lean/AgentMicrofoundations/AutoregressiveContext.lean`：把上下文混合接到固定自回归构成。若所有正概率上下文编码出同一完整 prompt 和同一生成预算，则混合后的任意行动事件概率恰等于参考输入下的条件概率。预算可依赖主体状态/资源，但需要在相关支持上相同。该定理不识别 token 核，也不声称不同输入会造成不同响应；它是“相同完整计算输入 ⇒ 相同响应分布”在不确定上下文下的可证伪推论。
- `lean/AgentMicrofoundations/PopulationInputShift.lean`：把相同完整输入的提议律不变性提升为人口层面的定量预测。对同一批匹配 agent，在每个 agent 自己的 token 核、停止规则、parser 和解码设置跨条件固定时，任一提议事件的期望总人数变化不超过完整输入签名（prompt、generation budget）改变的人数；平均发生率变化不超过其占比。允许 agent 间构成异质；不假设 agent 独立，也不预测改变输入的方向或具体选择。该 Lean 界适用于同人数匹配面板；跨 3/4/5/6 人配置的原始平均率还要单独处理成员构成和权重，不能直接套用。案例拒绝需完整输入、个体构成以及重复抽样误差均可核验。历史请求的逐 agent request-ID 顺序和最近上下文已从 24 个 world 的原始事件、panel 与日志中重建并核对；完整复放还包括 contemporaneous panel、system skill、tool schema 和规范化请求对齐。这是案例审计的剩余数据工程，不是理论构建或参数化实验设计的前置条件。
- `lean/AgentMicrofoundations/TokenAccounting.lean`：在 spendable Nat token balance、固定生成 token 单价、固定技术上限的显式特例下，定义可支付最大预算 `min(cap, balance / price)`（零单价时由技术上限约束），证明该预算可支付、技术上可行、具有最大性，且余额增加不会降低预算；证明提前停止后的实际生成成本不超过余额，余额扣款精确闭账。`ResourceBoundedResponseProcess` 将上述预算公式作为可检验的模型限制，接入自回归响应层。该结果不假定研究者支付的 API 费用属于 agent，也不覆盖 prompt 费用、非线性成本、信用或补贴。
- `lean/AgentMicrofoundations/CouplingComparativeStatics.lean`：用对所有事件概率相等而非 outcome 列表逐项相等来定义耦合边际，因此尊重分布中的重复项；证明支持上的事件嵌套可推出概率单调，并构造共同随机种子诱导的耦合。共同种子下逐样本事件保持足以推出生产概率单调，但实际 token 生成是否有跨预算一致的随机带语义、解析器是否逐样本单调，仍是待验证的限制。
- `lean/AgentMicrofoundations/AutoregressiveCouplingSensitivity.lean`：对固定计算构成的两个上下文，若提供前缀提案分布的有限耦合，证明完整解析后的事件概率对比不超过两端解析误差与耦合事件分歧之和。该结果把任意上下文不稳定响应转成可审计的敏感度界；配对耦合若无法由实验设计/日志支持，界可能很松，不能当作点预测。
- `lean/AgentMicrofoundations/ResourceBudgetComparativeStatics.lean`：在固定 token 核、停止规则、解析器的有限自回归例子中，形式证明可支付预算提高时某生产性提议概率从 1 降为 0；进一步把余额 1→2、单价 1、技术上限 2 代入。它反证从资源—预算单调性直接推出生产概率单调性的企图；并形式化证明这个例子不可能存在生产事件按支持嵌套的低/高预算耦合。这是逻辑存在性反例，不是对案例 agent 的经验描述，也未断言真实 parser 具备该特性。
- `lean/AgentMicrofoundations/OntologyExamples.lean`：构造两个关键拒绝边界：菜单随资源值变化但资源转移恒等，故静态资源相关不推出核支持的一步反馈；资源改变可行菜单但响应核忽略菜单，故资源相关不推出提议律/行为律随资源改变。两者分别区分“资源有经济后果的机会”与“过程实际到达该后果”，以及“机会集合变化”与“主体响应变化”，防止从资源约束偷渡理性或资源敏感偏好。
- `lean/AgentMicrofoundations/FiniteDynamics.lean`：只在明确提供模型—机制相容性证明后，定义 agent 完整单期结果及条件于该结果生成下一期上下文的转移核；上下文可与本期联合行动和生产相关。递归构造任意有限期轨迹分布，并证明逐期受支持的轨迹及受支持初始状态产生正路径质量。该模块支持将上下文与完整群体状态放进动态状态，但上下文生成核仍是外部提供的模型对象，尚未从训练/部署推出或用现有案例估计；不代表长期预测理论。
- `lean/AgentMicrofoundations/Accounting.lean`：可选的多资源坐标整数账本精化。它把抽象 `resourceAfter` 更新约束为逐 agent、逐资源坐标的期初余额加有来源类型的事件流（核验生产、外部供给/流出、运行成本、双边转移）；证明事件流可拼接、单笔转移只改变付款/收款双方在对应资源上的余额、两方该坐标余额和不变且其他资源坐标不变；进一步证明对显式列出且无重复的有限人口，只含同一资源内部转移、覆盖所有转移端点并满足逐主体闭账时，人口该资源余额总和不变。闭账等式与人口覆盖条件是该命题的显式前提，不是普遍公理；该会计恒等式不预测转移对象或行为概率，也不替实验验证日志来源。
- `lean/AgentMicrofoundations/GroupProbability.lean`：有限经验概率空间中的两主体团队成功率 Fréchet 界，不预设成员独立。
- `lean/AgentMicrofoundations/Commitments.lean`：把到期承诺和转账限额作为核心 `AgentState` 的可选合同扩展，形式化说明同一基础 agent 状态在义务不同的情形下支付可行性可不同。它说明遇到负债/承诺案例时需要扩展状态，不声称所有 agent economy 都有合同义务。
- `lean/AgentMicrofoundations/Liquidity.lean`：含收入、到期承诺和运行成本的期际现金流；证明逐期可履约蕴含非负终值，并给出正终值仍会早期违约的反例。
- `lean/AgentMicrofoundations/ResourceLedger.lean`：跨设置资源事件账本；区分经核验生产、边界外注入/流出、运行成本和内部转移，证明内部转移的总量中性、余额来源非识别、终值顺序不变及计量单位缩放不变。
- `lean/AgentMicrofoundations/Settlement.lean`：将到期承诺转成可用余额，区分自由转账与到期义务结算；证明可行条件等价式、转账守恒、承诺保留/清偿、净可用余额变化及拒绝时状态不变。
- `lean/AgentMicrofoundations/CausalInterface.lean`：记录单轮提议、机制执行门与固定潜在生产结果；证明核验产出数不超过执行数、执行数不超过提议数，关闭门时无核验产出，并给出“无提议”和“提议被拦截”在最终产出上不可区分的形式反例。它只适用于提议后开关执行且不改任务/生产条件的干预。
- `lean/AgentMicrofoundations/FiniteCoalitions.lean`：将团队“至少一人成功”的有限样本边界推广到任意团队宽度，不假设成员独立；给出任一成员边际作为下界、总成员成功数与试次数作为上界，并证明相同个体边际不识别组产出。
- `lean/AgentMicrofoundations/Symmetry.lean`：形式化对称性边界：同一个确定性响应规则下，完整输入相同必然给出同一行动；行动分化要求完整输入至少有一项不同。另以固定规则、变动上下文的有限例子说明，不需假设偏好改变也可产生不同选择。该模块不涵盖随机解码，也不证明真实实验中的分化机制。
- `lean/AgentMicrofoundations/Specialization.lean`：形式化“不同前向不变上下文区域 → 持续角色分化”的充分条件，并以整数上下文给出强化反馈例子：同一固定策略在一次相反经历后进入不同区域，之后角色一直分开。它证明稳定分工可由状态反馈产生，无需策略/偏好漂移；没有证明真实 agent 满足这些不变性条件，也没有给出进入不同区域的概率。

- `lean/AgentMicrofoundations/MechanismFeedback.lean`：将核验产出/计算成本形成的资源差，接入固定的阈值响应规则；证明跨过事先给定的资源边界会改变下一期行动、同处边界一侧则响应不变。它是可证伪的条件模型，不是对真实 LLM 响应规律的经验断言；目前尚无实验估计其阈值。
- `lean/AgentMicrofoundations/MechanismCounterfactual.lean`：新增把同披露机制比较落到命名干预族的排除限制：若两种制度在相同完整状态向每个 agent 给出相同制度信号，共享的响应模型就必须给出相同的首轮联合提议律和任意预先声明的提议事件概率；后续执行、生产、资源和上下文仍可不同。观测到首轮提议分布变化即拒绝“只改变下游执行”的案例映射，除非输入、机制披露或共享模型条件实际也改变。该定理用于逐项审计 CTF 的 vote/allocator 比较，不能直接套用于 prompt 或 panel 同时变化的处理。
- `lean/AgentMicrofoundations/AllocationIdentification.lean`：在不假设理性、均匀随机或个体独立的情况下，证明给定实际 recipient 数时任意组别曝光人数的尖锐界，并证明严格稀缺时容量本身不能识别具名 agent 的获配状态；有限经验轨迹及任意有限有理彩票的累计/期望群体曝光也满足同一尖锐区间，且证明期望上下端点可达。固定供给下的人口总曝光守恒给出 `m/N` 的人口平均机会率。它给出部分识别，不从机会容量编造个体概率，也不把有限样本频率冒充总体概率。
- `lean/AgentMicrofoundations/AnonymousAllocation.lean`：对有限有理分配彩票证明个体获配概率总和等于预期获配人数；若每个结果恰分配 `m` 个名额且分配彩票对人口标签的任意两两交换保持完整事件分布不变，则先推出等边际，再得任一 agent 满足 `N·p=m`；进一步对大小 `g` 的子组证明 `N·E[g]=g·m`。这是可检验的机制对称性限制，不假设主体独立或理性。
- `lean/AgentMicrofoundations/AllocationFeedback.lean`：将分配、资源更新和跨期响应接起来。异质性扩展 `AgentThresholdResources` 允许每位 agent 有自己的余额、运行/计算成本、产出和响应阈值；若某组每个成员各自满足 idle/失败低于自身阈值、成功跨过自身阈值，则 `heterogeneous_group_next_active_mass_eq_expected_productive_count` 证明该组下一期行动概率质量之和等于期望成功获配人数。无需组内同质、分配对称或独立性。定理 `failed_task_at_threshold_breaks_productive_response_identity` 给出明确边界反例：失败后仍在阈值上会使未成功者也激活，因此不能无条件使用桥接式。对称性仍只在将总量拆成某个具名 agent 的共同概率时需要；阈值响应本身仍是待拒绝的模型限制，不是从资源公理推导出的选择规律。
- `lean/AgentMicrofoundations/OpportunitySpecialization.lean`：将随机独占机会、共同初始上下文、暴露后状态、同一固定响应核和跨期角色持续性合成一个案例命题。只要每个正概率结果都产生两类暴露，且暴露分别进入不相交的前向不变响应区域，群体角色分化概率就是 1；分配彩票可依赖且不匿名，agent 身份不被点识别。一个整数强化例子明确展示这些前提如何成立。该预测能被逐期上下文和角色日志拒绝；现有 CTF 最小切片缺少相应逐 agent 关联，所以目前只是可复用的条件理论，不是 CTF 的已验证发现。
- `lean/AgentMicrofoundations/ResourceThresholdPersistence.lean`：将核验生产后的 agent 余额、共同每期资源消耗和阈值响应联结。对精确余额余量 $m$ 和消耗 $d$，Lean 证明第 $t$ 期活跃响应与 $td\le m$ 等价，并证明余量耗尽时响应关闭；若正概率生产分配均为部分生产，预测期内角色差异概率为 1。拒绝规则是：若核验的资源轨迹在 $td\le m$ 时跨回阈值，拒绝共同消耗/阈值响应限制；若 $td>m$ 后仍保持活跃，拒绝该模型的阈值选择限制。它不预测受益者身份，且不适用于角色依赖成本、后续资源补给或非阈值响应。
- `lean/AgentMicrofoundations/ResourceThresholdPath.lean`：定义带吸收死亡状态的逐事件资源门槛更新。Lean 证明存活路径的期末余额等于初始余额加逐事件净流量；跨阈值时，同净流量的不同事件顺序可以产生不同存活和余额。若案例在中间步骤裁决存活，聚合净变化不足以模拟后续机会；只有审计确认后端采用加总后统一裁决，才可用顺序不变账本简化。
- `lean/AgentMicrofoundations/SurvivalCurrency.lean`：把“货币余额同时作为可交易资源和续存所需储备”写成可推广机制。对有理数余额（包含 CTF 的分数调用成本），Lean 证明已执行转账对续存人数的净影响，恰等于收款方跨入阈值人数减去付款方跨出阈值人数；对任意有限异质阈值群体，达到续存门槛的主体所需阈值总和不超过货币总量；对统一储备，另有存活人数上界和总量不变但改变谁达到门槛的两主体例子。低于总储备阈值时，任何配置都不能让全体存活。这只推出机制与状态转移的条件性结果，不预测主体会提议/接受转移，也不把资源算术解释成生存偏好。它与稿件中余额 $r$ 和继续许可 $\rho$ 的分离兼容：同一余额可同时记作货币，但续存仍是门槛规则导出的状态变量。
- `lean/AgentMicrofoundations/CaseStudies/CTFAllocation.lean`：把 CTF 的六人、三任务、可选 4+2 示例数值代入通用容量/曝光界。组划分不是实验事实；实际身份组可任意从 case panel 查询。
- `lean/AgentMicrofoundations/CaseAnalysis.lean`、`CaseStudies/CTFModel.lean`、`CaseStudies/CTFTraceModel.lean`、`GroupPrediction.lean`：案例接口不固定人口数、组大小或预设分组。`GroupPrediction.lean` 将任意有限组作为查询对象；在每个组员都满足可检查的异质资源阈值桥接时，Lean 推出该组下一期活跃概率质量之和等于该组核验成功获配数的期望。结论不要求匿名分配、agent 独立或相同能力。阈值桥接不成立或未被数据支持时，接口不给出该数值预测；此时应报告拒绝/未识别，不得借用 4+2 示例的假设。

## 研究边界

项目的核心对象现已在 `Ontology.lean` 中明确分成 agent 状态/响应、模型条件、可见制度信号和机制执行层；可选 `ResourceBoundedResponseProcess` 进一步把可支付计算预算接入响应律。这个线性 token 计价特例证明资源增加弱提高最大生成上限，但不推导特定行动概率单调。资源是否属于 agent、实际成本 schedule 是否线性、状态编码是否充分、逐 token 核是否能由具体计算构成支持，仍需独立审计或实验识别。其他开放义务包括可达路径上的资源稀缺、训练/运行机制到行为规律的更深推导、跨人口规模的运输条件、以及有限联合核向更一般概率对象的扩展。每个前提仍须归类为模型定义、机制契约或待识别限制；不得从案例结果倒推公理。

当前 Lean 结果包含资源可行性算术、概率非识别反例、团队事件概率的有限样本边界、合同承诺/到期时间对流动性的影响、一个三期上下文持续率模型、单轮提议—执行—核验接口、确定性对称性边界、持续分工充分条件、机会稀缺配给容量界、资源差通过阈值响应影响下一期行动的条件性桥接，以及个体/组别分配身份的部分识别界。新增的分配与跨期模块在条件满足时把随机分配、随机生产、资源更新和下一期响应串成一条可证伪预测链。机会数少于人口会机械地产生未获任务者；给定实际指派数 $m$，组大小 $g$ 的获配数只能被界定在 $[\max(0,m-(N-g)),\min(m,g)]$。在 6 人、3 个实际 recipient 的 4+2 分组中，4 人组必有 1–3 人获配、2 人组可有 0–2 人获配。容量不识别具体是谁，也不识别获配概率。新增有限彩票定理给出一个可检验的个体预测：若每轮恰好分配 `m` 个名额且在给定输入条件下完整分配律对人口标签交换不变，则 `P(i 获配)=m/N`。Lean 已形式化完整事件分布对人口标签两两交换的不变性，并由此推出等边际；但 allocator-discretion 是否满足该限制仍须检验。主实验 allocator 还可能少于三次指派，因此这些数值结论必须以实际 $m=3$ 为条件。

这些结果应按“地基对象”和“领域扩展”区分，而不能把并列的 Lean 模块数量当成理论完整度。地基对象是计算主体身份/构成、动态状态与资源归属，条件响应和生产规律，执行机制，以及可核验的轨迹结果；流动性、合同、特定团队概率和 CTF 配置是对地基的扩展或案例化，不是 agent 本体定义所必需的公理。理论的主线必须回答：哪些规律从主体的计算与资源约束本身推出，哪些只能在给定响应/生产核后推出，哪些在缺少核时只能部分识别。当前不少定理仍是“给定行为规律后的推论”，核心未闭合处仍是从计算构成、上下文状态、可执行机会与主体资源边界中推出可复核的微观行为边界。

`ResponseIdentification.lean` 给出一个关键边界：可行集合同时允许事件与非事件时，单靠可行性限制的响应概率尖锐识别集是完整的有理区间 $[0,1]\cap\mathbb Q$。`AutoregressiveContext.lean` 则给出相反方向的精确限制：完整 prompt 和生成预算相同，固定自回归构成就必须给出相同提案分布。新增 `PopulationTransport.lean` 把两者之间的边界钉牢：即使 token kernel、停止规则和 parser 完全固定，只要人口规模变化被编码成不同 prompt，同一 constitution 仍能在两个规模上实现任意一对响应概率。因此“模型没变”不足以支持 6 人到 3/4/5 人的外推；可检验的运输限制必须约束规模变化如何改变完整输入，或约束 token kernel 对这些输入变化的响应。这个定理是架构类上的尖锐非识别结果，不是对特定 LLM 响应规律的经验断言。

`AutoregressiveCouplingSensitivity.lean` 给出相应的正向界：对同一固定 constitution 的两种输入，若能构造/观测前缀提案分布的耦合，则完整提案事件概率差至多为两边 full-parser 与 prefix-parser 的不一致质量，加上耦合下两边事件指示不同的概率。该结果容许响应随上下文任意不稳定；它不假设偏好稳定，而把可预测性精确落在可审计的前缀解析误差和耦合分歧上。若没有可辩护的配对机制，任意耦合可能给出接近 1 的松界，不能把形式上的存在性当作经验识别。

对主实验，应把制度写成“当选 allocator 在 60 秒窗口内向不超过三名不同 recipient 分配三项工作”，不能写成六名 agent 直接同时抢同一任务。原始 trace 现在证实 24 个 world 的任务机会、I1 的逐次 `assign_task` 提议与工具状态、执行 recipient、checker 结果和每日资源变化均可重建。I1 stage1 有 130 次提议，其中 127 次与执行事件按 task/recipient 对应；stage2 有 77 次提议，其中 75 次与执行事件对应。I3 的 129 个 stage1 执行和 54 个 stage2 执行由 backend mechanism 产生，没有 agent allocator proposal。资源回放对 24 个终态全部匹配。可据此分别估计主体提议、机制执行、生产核验规律；不应再说逐日指派与 checker 记录不存在。完整 gateway 输入已对 45,180 条 exchange 完成审计；精确 request signature 在归档中均唯一，因此输入完整性已解决，但历史数据不能估计同一精确输入下的随机响应波动。完整输入的存在不自动验证跨输入核不变性、频率运输或因果机制效应；这些必须是单独、可简单检验的案例限制。

成熟度判断：**地基由定义和结构推论构成，实验用于裁决明确的案例限制与冻结预测，而不是替地基提供公理。** 现有 Lean 引擎可以在不调用 LLM API 的情况下枚举有限联合轨迹；CTF 设计参数已进入统一记录。完整输入已经重建，但精确请求无重复，所以历史记录不能识别同输入随机响应核。零 API 案例审计现已覆盖账本/事件映射、资源—存活制度限制、stage-2 基线预测和既有微型 pilot；有限期 persistence 区间与两期精确可达集合已形式化，但 CTF 映射尚未实例化。若行为核仍无约束，理论报告识别集而不给伪精确点预测；若某项案例限制没有简单裁决操作，也不把限制塞入模型前提。当前口径见 `THEORY_FREEZE_0.5.md`，0.2–0.4 保留为历史版本。

## 公式与定理的准入标准

公式不因使用符号就成为理论。正式主线只保留满足至少一项标准的数学对象：它限制可观测分布/可行状态；给出非平凡的比较静态或边界；产生能区分竞争机制的反例/预测；或证明在明示限制下某个量可识别/不可识别。定义、账本恒等式、全概率展开、有限集合计数和优化目标记号可以为形式化服务，但必须标作接口/基准/计算步骤，不得计为新发现。新增定理的说明须回答：相较于仅有定义，预测集合具体缩小了什么？哪一类数据会拒绝它？若答不出，留在 Lean 教学/基础模块，不进入论文理论贡献。
