# 案例模型实验限制登记规程

> 本文件是研究流程规范，不是 agent 本体经济学的定义、公理或定理。它规定何种经验限制可以进入一个具体案例模型。

## 准入字段

每项案例限制至少登记：

1. 可运行的核验方法和核验单位；
2. 预先声明的拒绝条件；
3. 检查失败后的处置；
4. 当前状态，以及是否被用于数值预测。

缺少低成本、直接可执行核验的经验限制，不作为案例预测前提。若属于主体行为规律且需要模型调用，使用固定输入、最小配对重复的诊断；若该限制需要大规模或难以复现的验证，则当前案例不启用它，保留一般联合规律或部分识别结果。

## 裁决边界

- 后端规则可通过源码/配置审计和边界输入检查；这是实现映射核验，不是行为假设检验。
- 账本、事件链和身份关联可通过既有日志重放；核验失败时拒绝案例映射。
- 行为规律须先冻结，再用独立 world 或配对输入做拒绝检验；“未拒绝”不等于普遍规律成立。
- Lean 负责检查形式推理，不负责判断某项经验限制是否适合现实系统。
- 任何限制失败只拒绝相应案例实例；除非发现逻辑矛盾，不据此扩张或修改基础定义。

## 当前机器登记

具体限制、成本、证据和裁决结果由 [`analysis/validate_case_assumptions.py`](analysis/validate_case_assumptions.py) 写入 [`lean/verification/assumption_validation.json`](lean/verification/assumption_validation.json)。`lean/verify_micro.py` 会运行这些检查，确保未经验证的经验限制不会被标记为当前案例点预测前提。这个自动化检查验证的是研究流程记录，不是理论的科学真理。
